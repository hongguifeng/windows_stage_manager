# Windows 11 台前调度式窗口管理器需求说明

文档版本：1.6
文档状态：可用于实现与验收
适用平台：Windows 11，交互用户会话

## 1. 产品目标

程序以后台托盘应用运行，在不改变窗口尺寸的前提下，让用户容易辨认并点击被活动窗口遮挡的普通窗口。

核心体验：

1. 普通窗口从非活动变为活动时，可自动水平居中并与当前显示器工作区底部对齐，把空间留在上方。
2. 已活动窗口由用户手动移动后保持用户位置，不执行自动放置。
3. 后台窗口优先在左上或右上露出标题栏和一条侧边，两条通道应保持均衡。
4. 顶部最容易辨认，左侧次之；右侧和底部较难辨认，需要更大的可见区域。
5. 只有全部位置方案无解时才允许有限调整非活动窗口的 Z-order，并优先保护最近使用的上层窗口。

## 2. 稳定状态保证

Windows 事件异步到达，程序不承诺消除事件到达前的瞬时遮挡。每个事件批次收敛后必须满足以下之一：

- 所有受管理窗口达到当前可辨识目标；
- 求解器明确返回 `Unsatisfiable`、`Timeout` 或平台错误，且没有应用部分计划。

拖动期间允许短暂中间状态；`MOVESIZEEND` 或前台切换事务结束后必须重新捕获完整快照、求解并验证。

## 3. 窗口可辨识区域

### 3.1 分边规则

四条边分别配置动态长度与深度，不再使用统一的边缘长度、统一深度或边缘数量参数。

实际长度为：

```text
clamp(窗口对应边长 × LengthPercent, MinimumLengthDip, MaximumLengthDip)
```

计算结果按目标窗口 DPI 转为像素，并且不会超过窗口对应边长。

默认“平衡”配置：

| 边 | 最小长度 | 最大长度 | 动态比例 | 深度 |
| --- | ---: | ---: | ---: | ---: |
| 顶部 | 120 DIP | 240 DIP | 25% | 32 DIP 回退值 |
| 左侧 | 120 DIP | 240 DIP | 25% | 40 DIP |
| 右侧 | 160 DIP | 300 DIP | 30% | 64 DIP |
| 底部 | 180 DIP | 360 DIP | 35% | 64 DIP |

标准 `WS_CAPTION` 窗口的顶部深度必须优先使用从客户区原点、DWM 视觉框和系统 DPI 指标得到的实际标题栏高度。只有无边框、自绘标题栏或无法取得实际值时，才使用顶部回退深度。

### 3.2 可见与可点击

某条边合格必须同时满足：

1. 可辨识矩形位于窗口视觉框与当前工作区的交集内。
2. 未被更高 Z-order、同一显示器、当前桌面上的可见阻挡窗口覆盖。
3. 未遮挡部分包含一段同时达到该边实际长度和深度的矩形。
4. 代表点命中后，其根窗口归属于目标窗口；无法可靠命中的特殊窗口默认不纳入管理。

### 3.3 目标等级

首选目标为 `TopAndSide`：顶部加左侧或顶部加右侧。共享角部必须从两条边的计算中扣除，不能让同一个角落重复满足两个区域。

若完整位置求解明确证明 `TopAndSide` 无解，才降级到 `AnyRecognizableEdge`。单边软优先级为：顶部、左侧、右侧、底部。

## 4. 活动窗口放置

当且仅当普通窗口发生“非活动 → 活动”且 `PlaceActivatedWindow=true`、同批没有进入用户拖动事务时：

1. 以视觉框水平中心对齐当前显示器 `rcWork` 水平中心。
2. 视觉框底边对齐 `rcWork` 底边。
3. 若窗口高于工作区，则改为视觉框顶边对齐工作区顶边，保证标题栏可见。
4. 自动放置作为完整布局计划的一部分，计入每批最大移动数。

相同 HWND 的重复前台事件不得再次放置。已经活动的窗口经 `MOVESIZESTART/END` 手动移动或调整大小后，活动窗口位置固定为用户最终位置。

关闭开关时仍须修复被遮挡的后台窗口，只是不移动新活动窗口。

## 5. 自动布局策略

### 5.1 硬约束

- 活动窗口在当前事务中固定，后台求解器不得再次移动它。
- 不改变窗口宽高、激活状态、所有者关系或 topmost 状态。
- 移动后至少保留配置的屏上宽度和高度。
- 所有受管理窗口必须共同满足当前可辨识目标；不得只修好第一个被遮挡窗口。
- 候选不得使原本合法的更上层受管理窗口变为非法。

### 5.2 左右上方通道

求解器必须显式生成左上与右上候选：

- 左上：目标窗口顶部带位于阻挡窗口上方，同时左侧带位于阻挡窗口左侧。
- 右上：目标窗口顶部带位于阻挡窗口上方，同时右侧带位于阻挡窗口右侧。
- 多个后台窗口按 Z-order 从上到下修复；已有左/右通道负载较小时优先使用该侧，负载相同则确定性交替。
- 更深窗口可沿相应通道形成标题栏阶梯，但不得为了方向偏好破坏硬约束。

### 5.3 候选排序

硬约束通过后按以下字典序比较：

1. 可辨识等级：顶部加侧边优于任意单边；单边为顶部、左、右、底。
2. 左右通道数量差最小，并遵循确定性交替。
3. 窗口中心到工作区中心的归一化距离最小；横纵距离分别按工作区宽高归一化。
4. 移动窗口数、本次 Manhattan 距离、距稳定布局距离、边界偏离和方向切换更小。
5. 窗口身份与坐标作为稳定平局键。

中心距离仅是较后级指标，不得压过更容易辨认的顶部或顶部加侧边布局。

### 5.4 完整布局与超时

先运行有界全局位置搜索；需要时运行按 Z-order 从上到下的增量完整布局修复。每次移动后必须重新扫描全部受管理窗口。达到状态数或时间预算返回 `Timeout`，不能把尚未穷尽的搜索误报为 `Unsatisfiable`。

## 6. Z-order 回退

只有 `TopAndSide` 和 `AnyRecognizableEdge` 的纯位置方案都明确无解时才启用。

1. 候选仅包含同一布局中非活动、受管理、非 topmost、非 owned 的窗口。
2. 采用 top-prefix 保护：先保持最长的上层窗口前缀不变，从最深插入边界开始，无解才逐层向上扩大。
3. 同一边界内采用 bottom-first：从当前最底层候选向上枚举。
4. 目标只提升到该候选边界的下一层，不默认放到活动窗口正下方。
5. 每个候选顺序都重新运行完整位置求解；首个完整合法解立即返回。
6. 活动窗口不得重排，其他窗口不得越过活动窗口。

`Timeout`、几何复杂度超限或平台错误不得触发声称“无位置解”的 Z-order 回退。

## 7. 窗口范围与分类

支持当前交互会话、当前虚拟桌面、活动窗口所在显示器上的 1–20 个普通矩形顶级窗口。默认排除最小化、最大化、全屏、cloaked、`WS_EX_TOOLWINDOW`、`WS_EX_NOACTIVATE`、`WS_EX_TOPMOST`、Shell、菜单、提示、通知、owned 弹窗和查询不完整窗口。

HWND 不能单独作为长期身份；窗口销毁和同值句柄复用必须通过进程与实例代数区分。

## 8. 托盘与设置

中文托盘必须提供启用/暂停、可视化设置、快速参数和退出入口。默认 `dry_run=false`，安装后开箱即可实际工作。

设置包括：

- `PlaceActivatedWindow` 开关；
- 紧凑、平衡、醒目三个可辨识度预设；
- 顶、左、右、底各自的最小长度、最大长度、动态比例和深度；
- 最小屏上宽高、事件合并、刷新间隔、移动/状态/时间/窗口上限和连续失败阈值。

连续数值必须提供常用值和“自定义…”入口。可视化设置窗口必须说明每个值的含义、范围、DIP/像素换算，并同时画出四边不同大小的效果。修改任一分边参数后预设标记为自定义；最小长度与最大长度冲突时自动同步另一端。

旧设置键不再读取、保存或展示，也不提供兼容迁移。

## 9. 应用、验证与失败安全

移动和重排必须使用不激活目标窗口的 Win32 标志。调用后重新捕获窗口位置、尺寸、显示器、Z-order、topmost 和活动窗口，并再次运行同一可辨识规则。任何偏差都使整批失败并触发 reconciliation。

程序必须提供 `Ctrl+Alt+F12` 紧急停用、内部事件回流抑制、连续失败熔断和状态哈希防振荡。无法确认状态时不得继续批量移动。

日志至少记录事务、活动窗口、`activation_placement_used`、`affordance_goal`、`affordance_goal_degraded`、违规窗口、候选拒绝、位置/Z-order 计划、应用结果和耗时，不记录窗口内容或敏感文本。

## 10. 验收标准

1. 标准标题栏窗口使用实际标题栏高度；无边框窗口使用顶部回退值。
2. 默认配置中顶部深度小于左侧，右侧和底部所需区域大于顶部。
3. 完全重叠的两个普通窗口能生成左上或右上的独立顶部加侧边候选。
4. A → B → C 多层遮挡时，所有违规后台窗口都被处理，不能只移动最上层 C。
5. 三个以上后台窗口的左、右通道数量差不超过 1（几何硬约束只允许单侧时除外）。
6. 新活动窗口水平居中、底部对齐；超高窗口标题栏留在顶部；关闭开关时活动窗口不移动。
7. 相同活动窗口的重复前台事件和用户手动拖动不会触发再次放置。
8. 100%、150%、200% DPI 下各边参数独立缩放。
9. 宽屏与竖屏使用归一化中心距离，不因较长轴产生不成比例的空白。
10. 纯位置有解时不改变 Z-order；无解时最深局部调整优先，最近使用的上层窗口尽量不变。
11. Debug 与 Release 的 Configure、Build、全量 CTest 均通过；每个功能提交包含对应自动化用例。
12. 发布包默认实际应用窗口调整，包含中文设置、示意图、图标和示例配置。
