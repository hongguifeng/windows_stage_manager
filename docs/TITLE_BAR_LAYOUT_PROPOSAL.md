# 标题栏优先布局方案与算法

本文描述当前已实现的 `TitleBarLeftHalf` 布局算法。后台窗口的位置由 `solve_title_bar_layout` 求解，协调器负责快照、活动窗口放置、移动事务及执行后验证。

## 1. 目标与硬约束

布局首先保证窗口可辨识，再改善最近使用窗口的可达性：

1. 每扇参与管理的后台窗口，从可视左端开始连续露出至少半宽的标题区域，且这一段的完整保护高度无遮挡。
2. 按真实 Z-order 优先缩短上层后台标题栏与活动标题栏的距离。最上层后台窗口尽量紧邻活动标题上方，然后考虑第二、第三个窗口。
3. 适当露出侧条以增加辨识度；距离条件相同时偏好左上，其次右上或仅露出顶部。允许对齐、小幅右偏、横向共用一行等布局。
4. 每个被移动的窗口，其整个原生窗口矩形必须位于当前显示器工作区内；不改变窗口尺寸、Z-order 或所在显示器。

活动窗口的位置由激活放置设置或用户拖动决定，进入后台求解后固定不动。标题保护高度、连续左半宽度和整窗边界不能为距离或侧条让步。窗口正文允许被覆盖，侧边、底边或零散露出面积不能代替标题栏达标。

Z-order 是布局优先级，不是独立维护的使用时间列表；置顶、所属窗口等关系下，不保证它严格等同于历史访问顺序。

## 2. 输入模型与参与范围

一次求解使用同一份 `LayoutSnapshot`，每个窗口提供：

- `key`：窗口身份；`zIndex`：真实层级，数值越小越靠上。
- `placementRect`：原生窗口矩形，用于执行移动和检查整窗边界。
- `visualRect`：可视矩形，用于标题、侧条和遮挡计算。
- `workArea`、`monitor`、`dpi`：当前显示器工作区及缩放信息。
- `titleBarHeight` 及来源、`lastStableRect`。
- `managed`、`movable`、`visible`、`blocksVisibility`、`currentDesktop` 等状态。

后台目标是活动窗口以外、受管理、可见且位于当前桌面的窗口，按 `zIndex` 稳定排序。协调器按设置限制受管理数量，默认上限为 20；筛选阶段优先直接被活动窗口遮挡的窗口，同组内优先同进程、同窗口类的重复窗口。进入求解后仍使用真实 Z-order。

遮挡物不局限于受管理窗口。满足以下条件的窗口参与目标的遮挡判定：

- 可见、位于当前桌面且 `blocksVisibility=true`。
- `0 <= blocker.zIndex < target.zIndex`。
- 与目标同显示器；目标显示器标识为 0 时不按显示器过滤。

不可移动窗口保留原位，仍参与遮挡。完全独立、不与其他相关窗口重叠的窗口不参与整体重建；局部紧凑调整也不搬动完全不与更上层窗口重叠的窗口。

活动窗口通过显式索引和身份确定，不能假定它位于快照下标 0：数组前面可能存在非受管理的更高层遮挡物。

## 3. 标题栏与侧条的几何定义

### 3.1 坐标与保护高度

所有求解坐标均为物理像素，矩形采用半开区间，边界相切不算重叠。DIP 配置按窗口 DPI 向上取整换算；DPI 为 0 时按 96 处理。

设目标的可视矩形为 `[x, x+w) × [y, y+v)`，标题栏测量或系统基准为 `b`，则保护高度为：

```text
h = max(ceil(1.5 × b), ceil(topDepthDip × dpi / 96))
```

配置高度是保护高度下限，不再乘一次 1.5。没有标题基准时使用配置下限；若 `h > v`，目标不达标，不把要求裁成细条。

provider 默认使用系统 caption、frame、padding 估计，标记为 `SystemEstimate`。具有完整 `WS_CAPTION` 且客户区起点偏移不小于系统 caption 时，接受非客户区测量，标记为 `NonClientMeasurement`。自绘标题区域仍是保守几何估计，不保证识别了应用真实文字区域。

例如，96 DPI、基准 31 px、顶部配置 48 DIP 时，保护高度是 48 px。

### 3.2 连续左半标题

顶部配置长度先按比例和上下限求出：

```text
configuredWidth = min(w, clamp(floor(w × topLengthPercent / 100),
                              scaleDipCeil(topMinimumLengthDip),
                              scaleDipCeil(topMaximumLengthDip)))
q = max(ceil(w / 2), configuredWidth)
P = [x, x+q) × [y, y+h)
```

`P` 必须完整位于工作区内，且不与任何相关更上层遮挡物的 `visualRect` 相交。顶部配置长度上限不能压低半宽下限。

`analyze_title_bar_exposure` 直接求从可视左端起、在整个高度 `h` 内均无遮挡的连续宽度：

1. 若标题高度范围或左端不在工作区内，可见宽度为 0；否则初值为工作区内可容纳的标题宽度。
2. 遍历所有相关遮挡物。只要遮挡物与完整标题带相交，就用其左边缘截断当前连续宽度：
   `visibleWidth = min(visibleWidth, max(x, blocker.left) - x)`。
3. 当输入有效且 `visibleWidth >= q` 时达标。

因此，即使只遮住保护区中的一行像素，也会截断该位置之后的连续宽度；右半标题和分散片段不能与左半互换。

### 3.3 辅助侧条

左右侧条从 `y+h` 开始，宽度取对应侧边配置的 DPI 换算值，连续长度按窗口高度比例及配置上下限计算。侧条必须有足够的正文高度容纳，并完整位于窗口和工作区内、避开所有上层遮挡物。

侧条独立评分，不重复计算标题角部。标题达标但侧条不达标，仍算可辨识窗口；左右侧条同时达标也只给该窗口计一次侧条奖励。

## 4. 标题距离与布局排序

设活动窗口可视标题原点为 `(ax, ay)`，目标原点为 `(x, y)`，目标解析后的左侧条宽度为 `s`：

```text
dx = max(0, abs(x - ax) - s)
dy = y - ay
distance = dx² + dy²
```

距离比较使用标题左上角，不依赖窗口宽度或正文中心。一个侧条宽度内的横向错位不罚分，允许保留左侧辨识线索，也允许对齐或小幅右偏为下层腾出空间。

`Quality` 按下列顺序逐项比较，前项不同就不再比较后项：

| 顺序 | 指标 | 偏好 |
|---|---|---|
| 1 | 达标后台窗口数 | 更多 |
| 2 | 按 Z-order 排列的达标布尔向量 | 更上层窗口先达标 |
| 3 | 按 Z-order 排列的标题距离向量 | 字典序更小 |
| 4 | 已达标窗口之间的距离倒序数 | 更少 |
| 5 | 具有任一合格侧条的达标窗口数 | 更多 |
| 6 | 按 Z-order 排列的方向向量 | 字典序更小 |
| 7 | 各目标的连续可见标题宽度之和 | 更多 |
| 8 | 相对初始快照发生位移的后台窗口数 | 更少 |
| 9 | 各移动的 `abs(deltaX) + abs(deltaY)` 之和 | 更少 |

方向向量从优到劣为：位于活动标题上方且露左侧条、上方且露右侧条、仅上方、非上方且露左侧条、非上方且露右侧条、其余达标位置、未达标位置。“上方”指目标 `visualRect.top < active.visualRect.top`，是否真正无遮挡仍由完整标题判定负责。

距离向量优先于整体侧条奖励：不能为了改善许多旧窗口的侧条而把最近后台标题推远。它是逐窗口的字典序目标，并非强制所有窗口满足 `distance₁ <= distance₂ <= ...`；受空间约束时允许倒序。完全相同的评分保留已有结果。

## 5. 候选位置生成

`placements` 生成有限边界候选，不逐像素搜索整张屏幕。

### 5.1 整窗合法位置域

设原生矩形宽高为 `pw, ph`，可视左上角相对原生左上角的偏移为 `ox, oy`，工作区为 `[WL, WR) × [WT, WB)`：

```text
WL + ox <= x <= WR - pw + ox
WT + oy <= y <= WB - ph + oy
```

每个新位置通过同一平移量更新 `placementRect` 和 `visualRect`，保留尺寸及不可见边框偏移。没有合法位置域或目标不可移动时，只保留原位。输入矩形必须有效且满足 Win32 坐标范围要求。

不能只检查标题在屏内，也不在求解完成后再将窗口夹回屏幕。初始已越界但未移动的窗口不因保留原位而被视为已经修正。

### 5.2 标题禁入区域与直接锚点

对上层遮挡矩形 `B = [L,R) × [T,D)`，标题保护区与它相交的条件为：

```text
L - q < x < R
T - h < y < D
```

候选坐标来自这些禁入区域的边界、整窗合法位置域边界，以及当前位置和上次稳定位置。

以活动窗口和每个相关上层遮挡物为锚点，优先加入四个直接上方候选：

```text
(anchor.left - leftDepth,             anchor.top - h)
(anchor.left,                         anchor.top - h)
(anchor.left + leftDepth,             anchor.top - h)
(anchor.right + rightDepth - w,        anchor.top - h)
```

同时收集横坐标 `L-q、L、R、L-leftDepth、L+leftDepth、R+rightDepth-w`，纵坐标 `T-h、T、D`，在合法位置域内交叉组合。右上位置必须检查所有更上层窗口，不以整个已占用区域的最右缘作为唯一入口。

局部修复还加入与已达标下层标题相切的位置：若下层标题为 `[lx,lx+lq) × [ly,ly+lh)`，则补充 `x=lx-w、lx+lq` 和 `y=ly-v、ly+lh`，使上层窗口能在不盖住下层标题的位置停下。

### 5.3 按行重建的候选控制

每窗候选数量受 `min(maximumCandidatesPerViolation, 512)` 限制，候选去重并保留直接位置。

按行重建时，下层窗口尚待重新安排，因此不引入其旧标题的相切边界。交叉网格按 Y、X 降序遍历，并在占用候选额度前排除标题前缀与更上层窗口相交的位置，避免无效下部位置挤掉可用的上方行。重建网格每遍历 64 点检查一次时间预算。

该预过滤只控制候选生成，不能代替最终标题分析、整窗边界或全局安全验证。

## 6. 分阶段求解

所有阶段共用时间、状态和移动次数预算，始终保留已验证的安全结果。临时试排只存在于内存，不直接移动真实窗口。

### 6.1 初始化

验证输入和可见性规则，扫描全部受管理窗口的标题违约，建立按 Z-order 排序的后台目标列表，并计算初始质量。

若没有违约且 `optimizeTitleBarLayout=false`，直接返回 `NoViolation`。前台切换可请求优化，因此“已可辨识但距离较远”的重叠布局也能进入后续阶段。

### 6.2 快速安全修复

只处理未达标后台窗口，标题左端连续可见宽度为 0 的窗口优先，其余保持 Z-order 顺序。

对每个目标生成候选，仅保留自身标题达标且不碰任何已达标下层标题保护区的位置。局部选择按“标题距离、方向、移动距离”排序；找到的安全改善作为后续搜索的退路。

达到总时间预算的一半后不再启动新的快速修复目标；已经开始的候选检查仍受总截止时间和移动次数限制。后续搜索失败不会丢弃快速修复结果。

### 6.3 重叠组重建

若仍有后台标题未达标，从初始快照尝试四种整组方案，按 Z-order 安排相关重叠窗口：

- 两种按行布局：优先利用标题前缀完全位于活动窗口横向范围之外的侧方空间；其余位置按 Y 更大、X 更大、移动距离更小排序。其中一种额外降低 `x < active.left` 的非侧方候选优先级，为下层保留左侧通道。
- 两种上方布局：先比较标题距离，再比较方向和移动距离；分别采用左上、右上优先的方向平局规则。

按行方案使较窄标题可在同一高度从右向左填充，必要时再向上占用一整行保护高度。各候选都检查真实上层遮挡物，不能仅凭“相邻窗口错开”认定可见。

全部达标后跳过尚未执行的普通重建方案。每个重建结果须满足移动上限、初始已达标标题不退化、活动标题不退化，并且增加达标数，或全部后台标题达标且整体质量更好，才可替换当前结果。

### 6.4 最近后台窗口的锚定重建

为最上层后台目标生成近距离锚点，仅当它可移动且与更上层窗口重叠时执行。锚点必须自身标题可见、整窗合法；按标题距离、方向、移动距离排序，最多保留六个。

依次固定该窗口在每个锚点，再用两种按行方案安排其余窗口。已有完整布局时，第一后台标题距离比当前更远的锚点直接跳过；相同距离的锚点仍可尝试，因为它们给第二、第三个窗口留下的空间可能不同。

锚定结果沿用整组验收规则：有遮挡的近距离试排不能替换完整安全布局。左上、对齐、小幅右偏都参与比较，不为强求左侧条而牺牲标题覆盖或最近窗口的距离。

### 6.5 递归位移链

若仍有未达标目标，则以它们依次作为根，尝试联动腾位：

1. 将当前已达标后台标题及根目标列为必须达标集合。
2. 按 Z-order 找到集合中首个未达标目标，尝试自身可见的新位置。
3. 候选可以临时覆盖可移动的下层标题，但不能损害必须达标的固定下层窗口。
4. 按“受损下层标题数、标题距离、方向、移动距离”保留最多 24 个候选，再递归修复被影响的下层标题。
5. 分支失败则回退；只有整条链恢复全部必须达标标题，并通过全局质量、移动数及活动标题检查，才保存结果。

Z-order 不变使遮挡依赖指向下层。每根链最多使用约总状态额度的三分之一，并向子分支分配局部额度，防止第一个死路耗尽所有机会；递归只在总时间预算的前三分之四内展开。

### 6.6 完整布局的安全紧凑调整

仅当全部后台标题达标时执行，按真实 Z-order 做最多三轮调整。

每个目标只考虑标题距离不比已选位置更远的候选；候选必须自身可见、保护所有已达标下层标题，并使整组质量严格改善。下层调整可能使上层的侧条平局获得改善，后续轮次在同一批中继续处理。布局哈希未变化时提前停止。

这一阶段不强制每扇窗口露侧条，也不把完全独立的窗口拉入布局。轮数和共享预算限制意味着它不承诺达到全局最优或任意输入的绝对固定点。

### 6.7 剩余违约的有限宽度搜索

若仍有后台标题未达标，使用安全结果作为种子进行 beam search：

- 按 Z-order 逐个扩展后台目标。
- 每层按已处理目标前缀的质量保留最多 6 个布局。
- 未处理及保留原位的窗口仍留在快照中，参与对其他下层窗口的遮挡判定。
- 对保留节点重新计算全部目标质量；只有不破坏初始已达标标题和活动标题、未超移动上限、满足新增达标条件且优于当前结果，才保存。

完整布局不进入这一阶段。搜索预算耗尽时返回已保存的安全结果，不应用未闭合的中间布局。

## 7. 预算与输出

默认 `SolverLimits` 为：总时间 16 ms、状态数 512、每窗候选数 512、移动数 32。实际运行受设置覆盖；活动窗口放置若占用一次移动，协调器会从后台可用移动额度中扣除。六个锚点、两种锚定按行方案、三轮紧凑调整、六状态 beam 是算法内部上限。

时间检查是协作式截止，不是硬实时保证。预算限制搜索投入，不放宽安全要求，也不保证所有几何可行布局都能被搜索到。

最终重新扫描标题违约，仅为位置变化的后台目标按 Z-order 输出 `MovePlan`：

| 状态 | 含义 |
|---|---|
| `Solved` | 无剩余标题违约，存在移动 |
| `NoViolation` | 无剩余标题违约，无需移动 |
| `PartiallySolved` | 仍有违约，但已有可提交的安全移动 |
| `Timeout` | 没有可提交移动且搜索标记预算耗尽 |
| `Unsatisfiable` | 本轮未找到可提交移动，仍有违约 |
| `InvalidSnapshot` | 输入、参数或相关扫描校验未通过 |

`Unsatisfiable` 是本轮有限搜索的结果，不等同于几何无解证明。活动窗口覆盖整个工作区、目标窗口比工作区更大等情况，也不能通过缩小窗口、越界或改变层级来规避。

## 8. 执行验证与稳定性

协调器在后台求解前确定活动窗口位置，使用窗口身份、布局代次和事务保护执行计划，执行后回读实际位置，检查位置、尺寸、层级以及同一标题保护规则。求解成功只代表计划成立，不能代替原生窗口接受移动的证据。

前台切换可优化距离；普通无违约刷新不持续做美观重排。未完成布局在桌面安静至少 250 ms 后通过新快照补排，初始等待 500 ms，无进展时退避至最多 8000 ms；拖动、前台变化、右键抑制及停用会取消旧补排。DryRun 不排队执行后续真实移动。

`SnapshotStale` 表示桌面变化造成快照过期：暂停当前批次、保留修复意图，后续重新采样；它不增加或清空真实故障计数。实际枚举、执行及验证失败仍受协调器故障保护约束。

## 9. 诊断与验证入口

`background_title_plan` 日志以事务编号关联批次，记录活动 HWND、后台 HWND、Z-order，以及 `title_before`、`title_planned`、`active_title_planned`。坐标均为可视标题左上角，不记录应用标题或文件路径；规划位置不是实际执行位置。

`window_inspector --solve` 只读计算当前前台场景；`--solve-top` 模拟最上层受管理窗口激活。输出活动身份/索引、移动前及规划矩形、固定遮挡物、保护高度、所需宽度、连续可见宽度和剩余违约。模拟后续求解沿用实际活动索引，假设规划位置被接受，不调用真实 mover。

实现及回归入口：

- `src/solver/title_bar_solver.cpp`：距离、布局质量、候选生成和各求解阶段。
- `src/solver/visibility_analyzer.cpp`：标题高度、连续左半宽度、侧条与违约扫描。
- `src/platform/win32/window_provider.cpp`：窗口矩形、DPI 和标题基准来源。
- `src/window/mvp_coordinator.cpp`：活动锚点、事务、执行验证及补排。
- `tests/title_bar_solver_tests.cpp`：完整高度、左右半区、宽度差异、屏幕边界、DPI/边框、反复激活及小预算安全性。
- `tests/crowded_desktop_fixture.h`、`tests/distant_crowded_desktop_fixture.h`：匿名多窗口几何回放。
- `tests/mvp_coordinator_tests.cpp`：协调器接入、活动身份、补排和快照失效处理。

整体功能及运行设置见 [SOFTWARE_FEATURES.md](SOFTWARE_FEATURES.md)，模块设计见 [SOFTWARE_DESIGN.md](SOFTWARE_DESIGN.md)。
