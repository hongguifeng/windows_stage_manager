> 文件：`docs/SOFTWARE_FEATURES.md`

> 文档性质：当前实现说明（As-built）
> 适用版本：0.2.1
> 状态基准：以 `src/` 中的现有代码为准，更新日期为 2026-09-06
> 文档定位：本文件是当前软件功能的唯一基准；代码架构和扩展方法见 [软件设计文档](SOFTWARE_DESIGN.md)。研究背景见 `TITLE_BAR_LAYOUT_PROPOSAL.md`，提案不替代现状文档。

## 1. 软件概述

Windows Stage Manager 是一个运行在 Windows 11 系统托盘中的后台窗口管理工具。它在普通窗口切换到前台或用户结束拖动后，根据当前显示器工作区、窗口遮挡关系和用户配置，自动完成两类操作：

1. 可选地把刚从后台切换到前台的窗口放到用户指定的九宫格位置。
2. 移动被遮挡的后台窗口，使其保留可辨识、可点击的窗口边缘。

当前运行时只改变窗口位置：

- 不改变窗口宽度或高度；
- 不调整窗口 Z-order；
- 不激活被移动的后台窗口；
- 不把窗口迁移到其他显示器；
- 不处理最大化、最小化、置顶、工具窗口、owned window 和系统界面窗口。

代码中仍保留底层 Z-order 移动接口及其独立测试，但当前协调器不会生成或执行 Z-order 计划。运行日志中的 `planned_reorders` 固定为 `0`。

## 2. 运行方式

程序是单实例、无主窗口的托盘应用。第二个实例检测到已有实例后会直接退出。

启动后，程序会：

1. 从 `%LOCALAPPDATA%\WindowsStageManager\settings.ini` 读取配置；文件不存在时使用内置默认值。
2. 在 `%LOCALAPPDATA%\WindowsStageManager\logs\manager.log` 追加运行日志。
3. 安装 WinEvent 窗口事件钩子和低级鼠标钩子。
4. 启动窗口事件队列、状态协调器和定期快照刷新。
5. 在系统托盘显示当前状态。

程序监听前台切换、移动/缩放开始与结束、位置变化、显示、隐藏和销毁事件。事件会按时间窗口合并，显示器、DPI、工作区变化、定期刷新或事件队列溢出会触发窗口快照重建。

真正触发布局计算的主要时机是：

- 普通窗口发生前台切换；
- 用户结束移动或缩放操作。

单纯的显示、隐藏、销毁或定期刷新用于更新、校正内部状态，不保证立即启动一轮窗口移动。

## 3. 受管理窗口范围

程序采用保守筛选策略。窗口必须同时满足以下条件，才会成为可移动的受管理窗口：

- HWND、进程 ID 和实例代次均有效；
- 是顶层根窗口；
- 所需 Win32/DWM 信息读取完整；
- 位于当前虚拟桌面；
- 当前可见，且未最小化、未最大化、未被 DWM cloaked；
- 不是置顶窗口；
- 不带 `WS_EX_TOOLWINDOW` 或 `WS_EX_NOACTIVATE`；
- 本身不是 owned window，也没有达到实质尺寸的可见 owned window；
- 不属于已知系统界面窗口类；
- 宽度和高度均达到“最小屏上宽度/高度”的配置门槛。

当前明确排除的系统窗口类包括菜单、桌面、任务栏以及部分系统 XAML/UWP 宿主窗口，例如 `#32768`、`#32769`、`Shell_TrayWnd`、`WorkerW`、`Progman`、`ApplicationFrameWindow` 等。

不受管理不等于不参与遮挡判断。快照有效、真实可见且位于当前虚拟桌面的窗口，如果与受管理窗口同屏、位于其上方并与工作区相交，仍会作为只读遮挡物影响候选位置。隐藏、最小化、DWM cloaked、其他桌面/显示器、工作区外和位于所有受管理窗口之后的 HWND 会在进入求解器前剔除。

每次布局最多纳入 20 个受管理窗口，实际数量由 `max_managed_windows` 控制，且最小为 2。集合始终包含活动窗口；其余名额优先分配给：

1. 同一显示器上被活动窗口直接覆盖的普通窗口；
2. 覆盖比例更大的窗口；
3. 之后按现有 Z-order 顺序保留的其他同屏普通窗口。

## 4. 新激活窗口自动放置

### 4.1 生效条件

当 `place_activated_window=true` 时，普通受管理窗口从非活动状态切换为活动状态，程序会根据水平和垂直配置计算目标位置。

水平位置有三种：靠左、水平居中、靠右。垂直位置有三种：靠上、垂直居中、靠下，因此一共可以选择 3×3 个位置。默认是“水平居中 + 靠下”。对齐以活动窗口所在显示器的工作区为基准，不包含任务栏占用区域。

先按 DWM 可视矩形对齐，再把整个 placement rect 限制在工作区内，之后才求解后台布局。窗口本体宽或高超过工作区时跳过自动放置，不缩放、不产生越界移动。

### 4.2 不会自动放置的情况

以下操作不会把活动窗口重新拉回配置位置：

- 窗口已经处于活动状态，用户继续手动移动或缩放它；
- 激活窗口后确实发生了人工拖动或缩放；
- `place_activated_window=false`；
- 右键点击导致窗口激活或打开上下文菜单；
- 活动窗口不符合受管理窗口条件。

用户完成真实拖动后，活动窗口最终位置优先，程序只以该位置为基础重新安排后台窗口。

部分窗口在点击边框时会先报告“移动/缩放开始”，即使鼠标还没有真正改变窗口位置。程序会区分是否收到实际位置变化：没有实际变化时仍执行新激活窗口放置；确实变化时尊重用户操作。

### 4.3 右键激活抑制

右键仅用于激活窗口或使用上下文菜单，不应触发自动放置或后台布局。

为兼容不同 UI 框架上报前台事件的时机差异，程序同时采用两种判断：

- 前台事件到达时检查右键是否仍处于按下状态；
- 通过 `WH_MOUSE_LL` 记录右键按下时鼠标所在的根窗口，并在释放时刷新时间，在释放后 1500 ms 内匹配延迟到达的前台事件。

一旦识别为右键激活，抑制状态会覆盖上下文菜单弹出、关闭并返回原窗口的过程；切换到另一个普通受管理窗口后恢复正常布局。

## 5. 后台窗口可辨识布局

### 5.1 标题栏左半区

主目标为 `TitleBarLeftHalf`：从可视左端开始至少连续露出窗口宽度的一半，而且这一段的完整标题栏高度无遮挡。右半标题栏、零散片段相加、只有侧边或底边均不能代替该条件。

保护高度为 `max(ceil(1.5 × titleBarHeight), DPI 换算 topDepthDip)`，同时用于遮挡判定、候选间距和移动后验证，不允许降为细条。`titleBarHeight` 区分可靠非客户区测量与系统估计；自绘标题栏仍按保守矩形估计。配置是保护高度下限，不再重复乘 1.5。例如 96 DPI 下系统基准 31 px、配置 48 DIP，保护高度为 48 px。

```text
配置长度 = min(窗口边长, clamp(窗口边长 × 比例, DPI 换算最小长度, DPI 换算最大长度))
标题栏所需宽度 = max(ceil(窗口可视宽度 / 2), 顶部配置长度)
```

旧配置的 25% 和 240 DIP 上限不会把主目标截断到半宽以下，无需重置设置。左右参数控制辅助侧条，底边参数保留给通用求解器和设置兼容。

### 5.2 遮挡与侧条

所有同屏、当前桌面、可见且 Z-order 更高的窗口都参与遮挡判断，包括不可移动窗口。遮挡矩形只要与标题栏高度范围相交，就截断左端连续可见长度；缺少一行高度也不算达标。

左上阶梯优先露左侧竖条，右上分支允许露右侧竖条。侧条从标题栏底部开始，独立检查连续长度和完整宽度，不重复计算标题栏角部。空间不足时允许只有左半标题栏达标。

### 5.3 左右上方阶梯

以活动窗口和更上层窗口为锚点生成候选：

- 左上：`left = anchor.left - leftDepth`；
- 右上：`right = anchor.right + rightDepth`；
- 相邻阶梯节点的纵向间隔为上述保护高度，至少为标题栏基准的 1.5 倍，不搜索缩减高度的候选。

额外搜索标题栏保护区与遮挡物相切的边界位置，以寻找右上分支入口。右上分支必须避开已有左上窗口，不能只检查活动窗口，也不要求一律移到整个已占用区域的最右端之外。必要时利用沿边界的横向位置、侧方或下方空间，仍需露出左半标题栏。

整个 placement rect 必须位于当前显示器工作区内。placement rect 与 visual rect 平移量一致，尺寸和 Z-order 不变，不存在求解后夹回屏幕而重新制造遮挡的步骤。

### 5.4 排序与稳定性

先快速修复未达标窗口，左端标题前缀完全不可见的窗口优先，其余保持 Z-order 顺序；每次改善立即保存，并保护所有已达标下层标题区域。若仍有遮挡，尝试重新安排重叠窗口组：宽标题按行放置，窄标题利用侧方并保留通道；必要时递归联动下层窗口腾位。只有完整方案保证原本达标的窗口不退化、达标总数增加时才应用，不会执行内存中临时遮挡的中间布局。最后用剩余预算按 Z-order 从上到下扩展候选，每层保留最多 6 个布局状态，依次比较：

1. 标题栏达标窗口数；数量相同时优先上层窗口。
2. 按真实 Z-order 逐个比较标题栏距离：先让第一后台标题最近，再考虑第二、第三个。比较标题左上角，不再比较到活动窗口正文的距离；一个左侧条宽度内的横向错位不罚分，保留左右辨识线索。
3. 距离倒序数、辅助侧条数量和方向，偏好左上 > 右上 > 仅顶部，再考虑侧方、下方。
4. 额外标题栏宽度、移动数和总位移。

第四版在安全重建之外增加最多六个近距离锚点：先固定最上层后台窗口到活动标题上方（左偏、对齐、右偏均可），再尝试两种按行方式安排其余窗口。整组仍全部达标且距离质量改善才替换完整退路，不能为拉近一个窗口重新盖住另一个。全部达标后使用最多三轮安全紧凑调整，只有未达标时才继续六状态 beam。标题高度、整窗边界、尺寸和层级保护均不放宽。

距离顺序在空间冲突时可以放宽；有界搜索不保证全局最优。完全不与更上层窗口重叠的窗口保持原位。普通修复中标题栏全部达标则返回 `NoViolation`；前台激活事务还会优化已有重叠布局的距离和侧条。周期刷新不会持续为几像素收益重排。

同类型优先发生在最多 20 扇 managed 窗口的筛选阶段：直接被活动窗口遮挡的 peer 优先；同组内 `processId + className` 重复窗口优先。进入求解后使用真实 Z-order。

## 6. 求解与部分布局

主流程只使用标题栏左半区目标，不再降级到任意边。空间不足时尝试更紧凑位置、放弃辅助侧条或接受距离倒序，侧边或底边不能计为标题栏达标。

每个候选受整窗边界、移动数、候选数、状态数和时间预算约束。每层对保留结果检查全部窗口，包括尚未移动的下层窗口。部分布局必须新增至少一扇达标窗口，且不能破坏任何原本达标窗口。大窗口无解时可以保留原位并继续改善较下层的小窗口。

预算耗尽时返回已经验证的安全改善；没有改善则保持原位，求解器标记 `Timeout` 或 `Unsatisfiable`。后者仅表示有限候选内无安全改善，不是一般几何无解证明。后台无解但本次有合法激活移动时，可以只执行激活移动并标记部分完成。

超时、部分布局或执行后要求重新核对时，保留后台补排意图；定期 `Reconcile` 在桌面至少稳定 250 ms 后重新抓取快照，初始等待 500 ms，没有进展时倍增至最多 8000 ms，有移动进展后恢复 500 ms。重试不重复放置活动窗口，也不进行纯外观优化；完成后停止。拖动、前台切换、右键抑制、停用和活动窗口身份/屏幕失效会取消旧补排。DryRun 不排队重试。窗口枚举期间的暂时变化（`snapshot_stale`）只暂停本次操作，保留补排并在快照恢复后继续，不计入永久停用阈值；真实枚举/API/验证失败仍保留熔断保护。

前台切换最多立即抓取三次快照，新前台暂时缺失时保留激活意图，由后续定期 `Reconcile` 恢复。活动窗口完全覆盖工作区等情况下，保留尺寸和层级可能使目标无法满足。

## 7. 移动执行与安全校验

每一批移动都有事务 ID 和布局代次。新拖动、新前台切换、暂停或设置变更会取消旧事务，防止过期方案继续执行。

实际移动前后会校验：

- HWND、进程 ID、窗口实例代次仍然匹配；
- 移动前位置仍与求解快照一致；
- 窗口尺寸没有变化；
- 窗口样式、扩展样式、可见性、显示器和置顶属性没有变化；
- 移动后位置与计划位置在 2 像素容差内一致；
- 最终 Z-order 与求解前一致；
- 最终可见性满足完整解或部分解声明。

Win32 位置更新使用“不改变尺寸、不改变 Z-order、不激活窗口、不改变 owner 层级”的标志。任一步失败都会停止当前批次并要求重新获取快照。

程序会识别自己产生的 `LocationChange`，避免把自动移动误当作用户拖动。窗口拒绝移动或在移动过程中销毁时，本轮事务会进入 API 错误或重建状态。

连续基础设施失败达到 `max_consecutive_failures` 后，自动管理会被关闭，以避免在窗口状态不可确认时继续移动。

## 8. 托盘交互

### 8.1 托盘图标

- 左键单击：在“启用管理”和“暂停管理”之间切换。
- 右键单击：打开使用当前界面语言的上下文菜单。
- 工具提示按当前语言显示：运行中、已暂停、无可用布局、API 错误或正在重建。

右键菜单包含：

- 暂停管理 / 启用管理；
- 打开可视化设置…；
- 快速参数设置；
- 退出。

### 8.2 可视化设置

“打开可视化设置…”按当前界面语言提供全部可调参数的名称、说明、单位和合法范围。简体中文和英文均覆盖窗口标题、字段列表、候选值、说明、按钮、校验错误以及预览文字。DIP 参数会按设置窗口所在显示器的 DPI 显示近似像素值，并在预览画布中展示至少半宽的顶部区域和标题栏下方的左右辅助侧条。底边不会在预览中作为主布局目标高亮。

用户可以连续修改多个参数、恢复默认值，然后保存并应用。应用配置时，程序会取消当前事务、重启内部窗口管理组件、通过临时文件写入配置并立即使用新设置，无需重启托盘程序。

### 8.3 快速参数设置

快速菜单显示每个字段的当前值和常用选项。连续数值字段还提供“自定义…”入口，可输入合法范围内的整数。

“Interface language / 界面语言”提供“English”和“简体中文”两个选项。通过托盘修改后，菜单、工具提示、无解通知和之后打开的设置窗口立即改用新语言，并写入配置文件；无需重启应用。默认语言为英文。

修改任一边缘长度、深度或比例后，`affordance_preset` 会变为“自定义”。如果最小长度超过当前最大长度，程序会同步抬高最大长度；如果最大长度低于当前最小长度，程序会同步降低最小长度。

### 8.4 紧急停用

全局快捷键 `Ctrl+Alt+F12` 会立即关闭自动管理、取消当前移动事务并保存 `enabled=false`。之后可通过托盘“启用管理”恢复。若快捷键已被其他程序占用，注册可能失败，程序当前不会额外弹窗提示。

## 9. 配置参考

### 9.1 基础行为

| 配置键 | 默认值 | 可选值/范围 | 功能 |
|---|---:|---|---|
| `enabled` | `true` | `true` / `false` | 是否启用自动管理；主要通过托盘或紧急快捷键修改 |
| `dry_run` | `false` | `true` / `false` | `false` 实际移动；`true` 只求解、记录日志，不调用窗口移动 API |
| `place_activated_window` | `true` | `true` / `false` | 是否自动放置新激活窗口；关闭后仍会修复后台窗口 |
| `activation_horizontal_alignment` | `1` | `0` 靠左、`1` 居中、`2` 靠右 | 新激活窗口水平位置 |
| `activation_vertical_alignment` | `2` | `0` 靠上、`1` 居中、`2` 靠下 | 新激活窗口垂直位置 |
| `affordance_preset` | `1` | `0` 紧凑、`1` 平衡、`2` 醒目、`3` 自定义 | 四边可辨识参数组合 |
| `ui_language` | `1` | `0` 简体中文、`1` English | 托盘菜单、工具提示、通知及设置窗口使用的界面语言 |

### 9.2 平衡预设下的边缘参数

| 配置键 | 默认值 | 自定义范围 | 功能 |
|---|---:|---:|---|
| `top_minimum_length_dip` | 120 | 1–8192 DIP | 顶部可见长度下限 |
| `top_maximum_length_dip` | 240 | 1–8192 DIP | 顶部配置长度上限，不能降低标题栏半宽下限 |
| `top_depth_dip` | 32 | 1–8192 DIP | 顶部保护高度下限，与标题栏基准的 1.5 倍取较大值 |

## 10. 状态、提示和日志

### 10.1 托盘状态

| 状态 | 含义 |
|---|---|
| 运行中 | 管理器正常接收事件，可处于空闲、拖动、DryRun、已应用或部分完成状态 |
| 已暂停 | 用户停用或安全熔断后不再执行自动布局 |
| 无可用布局 | 当前批次无安全方案，或活动窗口暂时不满足布局条件 |
| API 错误 | 快照、移动或验证失败 |
| 正在重建 | 正在刷新窗口状态或重启内部组件 |

### 10.2 无解通知

首次进入 `Unsatisfiable` 状态时，托盘会显示“窗口布局暂时无解”通知，说明程序没有改变窗口层级。程序会在下一次前台切换、拖动结束等布局触发时重新求解。通知请求显示 5 秒，相同提示至少间隔 10 秒，且只有从其他状态重新进入无解时才会再次尝试显示。

部分布局成功时不会显示无解通知；日志会记录尚未满足的窗口数量。

### 10.3 诊断日志

每批处理会写入 `batch_complete`，主要字段包括：

- `status`、`reason`：批次状态与暂停原因；
- `snapshot_windows`：Windows 捕获到的全部根级顶层窗口数；
- `solver_windows`、`managed_windows`、`blocking_windows`：过滤后的求解对象、可移动目标和只读遮挡物数量；
- `moved_windows`：本批实际涉及的窗口数；
- `solver_states`、`duration_us`：搜索规模与耗时；
- `planned_moves`、`applied_moves`：计划和已应用的位置移动；
- `planned_reorders=0`、`applied_reorders=0`：当前运行时不使用 Z-order 调整；
- `affordance_goal=title_bar_left_half`：最终使用的可辨识目标；
- `affordance_goal_degraded=false`：主目标不降级到任意边；
- `apply_status_code`、`failed_move_index`、`apply_last_error`、`apply_snapshot_status_code`、`apply_snapshot_last_error`：执行失败环节、计划索引与系统错误诊断；
- `solver_elapsed_ms`：纯求解耗时，区别于整批 `duration_us`；
- `background_retry_used`、`background_retry_pending`、`background_retry_delay_ms`：本批是否补排、是否排队继续、等待间隔；
- `fallback_used`：是否使用逐窗位置修复，不表示 Z-order fallback；
- `partial_layout_used`、`remaining_violation_count`：是否只完成安全部分布局；
- `activation_placement_used`：是否执行新激活窗口放置；
- `activation_layout_suppressed`：是否因右键激活而抑制布局；
- `queue_depth`、`total_dropped_events`：事件队列状态。

程序退出或内部管理器因设置变更而重启时，会写入 `runtime_summary` 汇总批次数、事件数、移动数、失败数、最大队列深度和最大批次耗时。

## 11. DryRun 模式

`dry_run=true` 时，程序仍会完成事件处理、快照、窗口筛选、候选生成、布局求解和日志记录，但不会调用 Win32 API 移动真实窗口。

该模式适合：

- 首次运行前观察软件将如何处理当前桌面；
- 调整边缘参数后查看 `planned_moves` 和降级状态；
- 复现问题时确认是求解问题还是窗口拒绝移动；
- 在安全熔断后重新启用前进行诊断。

默认值是 `dry_run=false`，因此发布程序开箱即会实际执行窗口调整。

## 12. 当前限制和非目标

- 仅面向 Windows 11 交互式桌面会话。
- 安全桌面、UAC 界面和完整性级别更高的进程可能无法读取或移动。
- 当前不执行跨显示器全局布局；只处理活动窗口所在显示器。
- 当前不改变 Z-order，即使位置方案无解也不会重排窗口。
- 当前不改变窗口大小，不提供平铺、分屏或自动缩放。
- 当前不包含动画、窗口缩略图、任务分组、虚拟桌面切换或工作区保存/恢复。
- 当前没有安装程序、自动更新和开机自启动管理；发布方式是便携 ZIP/EXE。
- 界面支持英文和简体中文，默认英文。
- 透明、圆角、非矩形窗口和自绘点击区域按矩形近似处理。
- 应用主动回弹位置、Windows Snap 介入或窗口在事务中销毁，可能导致本轮取消并重建。
- 求解受时间、状态数、候选数、移动数和区域复杂度上限约束，复杂桌面可能得到部分布局或无解。
- `scenario_runner` 的性能数据只适合在同一机器、同一构建类型下做回归比较，不代表通用性能指标。

报告问题时，建议提供：软件版本、复现步骤、显示器分辨率/DPI/任务栏位置、相关窗口类型，以及 `manager.log` 中对应的 `batch_complete` 行。日志可能包含 HWND、进程 ID、窗口类名和矩形位置，对外分享前应先检查隐私信息。
